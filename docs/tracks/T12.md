# T12 · Vendor Batch Acceptance under Audit Budget

**Độ khó:** CPU · trung bình · **Topic Day06:** H3, D1, H1 · **Fixture:** `fixtures/t12_vendor_batches/` · **Config:** `configs/tracks/t12.yaml`

> Với budget audit cố định, ước lượng tỉ lệ lỗi mỗi batch vendor kèm độ bất định và quyết định ACCEPT / REWORK / HOLD.

**5 bước bắt buộc:** Load vendor batches → Chọn samples theo budget → Ước lượng lỗi + uncertainty → Human inspect case khó → ACCEPT / REWORK / HOLD

## 1. Dữ liệu có sẵn (offline)

| File | Nội dung |

**Pipeline không được đọc `gt/`** (GT guard trong `src.main` sẽ dừng với exit code 5).

**Dữ liệu thật (tuỳ chọn, nếu giảng viên đã chuẩn bị `data/real/`):** Mô phỏng 5×1000 do giảng viên sinh bằng generator trong repo private (thử 1–5% & nêu CI).

## 2. Output contract

`out/batch_decisions.csv`: `batch_id, est_error_rate, decision ∈ {ACCEPT, REWORK, HOLD}, n_audited` (bắt buộc) + `ci_low, ci_high` (khuyến nghị).

Batch thiếu trong file được tính là **ACCEPT** (worst case — batch xấu bị bỏ lọt).

`src.main` kiểm tra file và cột bắt buộc; thiếu → exit code 2.

## 3. Metric (đã cài sẵn trong `src/metrics/tracks.py::eval_t12`)

- **Primary (báo riêng, không cộng)** — MAE của error-rate estimate **và** Bad-batch Recall (batch xấu không bị ACCEPT).
- **Guardrail:** HOLD rate ≤ `max_hold_rate` (mặc định 0,4). "HOLD tất cả" đạt bad-batch recall 1,0 nhưng FAIL guardrail — báo baseline tầm thường này cạnh PoC.
- Secondary: false reject rate, HOLD rate, CI coverage, budget violations (luôn kiểm khi có policy), cost/decision.

## 4. Baseline (nhóm tự cài) + thí nghiệm công bằng

- **Baseline:** Simple random sampling với cùng budget cố định/batch.
- **Protocol:** Batch 100 → tối thiểu 15–20 audit; không đọc GT ngoài oracle. Ví dụ:
```python
from src.common.audit_oracle import AuditOracle
oracle = AuditOracle('fixtures/t12_vendor_batches/gt/hidden_errors.csv', 'sample_id', 'is_error', 'batch_id', budget_per_group=20, audit=ctx.audit)
```
(Pipeline chạy với GT guard — oracle là đường hợp lệ duy nhất.)
- Cùng pool / budget / seed 42 / heldout cho baseline và PoC. Báo cả kết quả bằng 0 hoặc âm.

## 8. Gợi ý hướng nghiên cứu (không phải đáp án)

Stratified sampling theo `risk_tag`; Wilson CI (`src.metrics.wilson_ci`); sequential probability ratio test; quyết định dựa trên CI chứ không point estimate.

**Giới hạn của n = 20 (nên đưa vào report):**
- Clopper–Pearson một phía 95%: 0 lỗi/20 → cận trên ≈ 13,9%; 1 lỗi/20 → ≈ 21,6%. Tức với budget 20, **không thể chứng minh** batch đạt ngưỡng 5% — "chưa thấy lỗi" ≠ "đạt".
- Chọn khoảng: Wilson hoặc Jeffreys cho n ≤ 40, Agresti–Coull cho n ≥ 40; **tránh Wald** (Brown, Cai & DasGupta 2001).
- AQL của ISO 2859-1 là mức chất lượng chấp nhận được của một kế hoạch lấy mẫu, không phải ước lượng tỉ lệ lỗi của batch.

**Tài liệu gốc:** CVAT QA · ISO/IEC 5259-5:2025 · ISO/IEC TR 5259-6:2026 · Brown, Cai & DasGupta (2001) *Interval Estimation for a Binomial Proportion*, Statistical Science 16(2) · ISO 2859-1 (xem Research Shelf trong handout).
