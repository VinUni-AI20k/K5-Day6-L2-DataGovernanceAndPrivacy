# T11 · Post-label Error Review Prioritizer

**Độ khó:** CPU · trung bình · **Topic Day06:** G3, H3, G2 · **Fixture:** `fixtures/t11_label_errors/` · **Config:** `configs/tracks/t11.yaml`

> Chấm suspicion score cho annotation để người review B mục tìm được nhiều lỗi nhãn nhất (class swap, box shift, duplicate, missing).

**5 bước bắt buộc:** Parse bbox & classes → Tạo suspicion score → Rank theo budget → Review + sửa labels → Xuất changed labels + scores

## 1. Dữ liệu có sẵn (offline)

| File | Nội dung |
|---|---|
| `images/*.jpg` + `images.csv` | 55 ảnh, split dev / heldout (30%). |
| `annotations.csv` | ~200 bbox **đã bị chèn lỗi**: `ann_id, image_id, class, x, y, w, h`. |
| `model_predictions.csv` | Dự đoán detector **mô phỏng** (`conf`) — không phải sự thật. |
| `gt/gt_errors.csv`, `gt/clean_annotations.csv` | Lỗi thật + nhãn sạch — chỉ evaluate. |

`manifest.csv` (input) và `gt/manifest.csv` (ground truth) chứa `source, license, split, sha256` — pipeline kiểm hash ở bước load.
**Pipeline không được đọc `gt/`** (GT guard trong `src.main` sẽ dừng với exit code 5).

**Dữ liệu thật (tuỳ chọn, nếu giảng viên đã chuẩn bị `data/real/`):** `data/real/coco/boxes.csv` hoặc `data/real/bdd/detections.csv`: tự inject lỗi (log trong manifest) để kiểm thử trên nhãn thật.

## 2. Output contract

`out/ranking.csv`: `item_id, score` — `item_id` là `ann_id` (lỗi trên box có sẵn) hoặc `img:<image_id>` (ảnh thiếu box).

`src.main` kiểm tra file và cột bắt buộc; thiếu → exit code 2.

## 3. Metric (đã cài sẵn trong `src/metrics/tracks.py::eval_t11`)

- **Primary — Error Recall@B** = lỗi thật trong top-B / tổng lỗi thật trong heldout; **B = max(10, 10%·N)**. Evaluate in ra *oracle ceiling* = min(1, B/#lỗi).
- Secondary: Precision@B, error-type coverage, minutes/defect, wrong-correction rate.

```bash
python -m src.evaluate --track t11 --pred out/ranking.csv
# lưu kết quả để nộp:
python -m src.evaluate --track t11 --pred out/baseline/<file> --run-name baseline --out reports/metrics_baseline.json
python -m src.evaluate --track t11 --pred out/poc/<file>      --run-name poc      --out reports/metrics_poc.json
python -m src.compare reports/metrics_baseline.json reports/metrics_poc.json --out reports/table1_baseline_vs_poc.md
```

## 4. Baseline (nhóm tự cài) + thí nghiệm công bằng

- **Baseline:** Random B mục, seed 42 (có sẵn: `--pipeline src.examples.random_baseline`).
- **Protocol:** GT lỗi và prediction mô phỏng tách khỏi scoring logic; so trên cùng heldout pool; 30% cases giữ kín khi tune.
- Cùng pool / budget / seed 42 / heldout cho baseline và PoC. Báo cả kết quả bằng 0 hoặc âm.

## 5. Failure mode bắt buộc phải phân tích

Tối ưu trên lỗi injection quá dễ; chỉ bắt bbox ra ngoài biên mà bỏ qua class swap hợp lệ.

Fixture đã cài sẵn một số case cho các failure mode này — nhóm phải tự tìm, minh hoạ bằng ảnh/metadata và nêu root cause.

## 6. Human review + quyết định

Contact sheet trước/sau + log ai sửa; giữ nguyên raw + diff.
Dùng `src/common/review.py` (queue, overrides, `AuditLog`), `src/common/contact_sheet.py` (HTML offline có nút Export CSV) và `src/common/decision.py` (GO/HOLD/REWORK + `reason_code` + `owner`).

## 8. Gợi ý hướng nghiên cứu (không phải đáp án)

IoU/class disagreement với prediction; duplicate = IoU cao cùng ảnh; missing = prediction conf cao không khớp annotation nào.

Đối chứng: `cleanlab.object_detection.filter.find_label_issues` (cần prediction). **Oracle ceiling:** Error Recall@B tối đa = min(1, B / #lỗi) — với fixture mặc định là **0,909** (evaluator in trong notes); so kết quả với trần này, không phải với 1,0.
