# T06 · Dataset Semantic Integrity & Provenance Gate

**Độ khó:** CPU · trung bình · **Topic Day06:** D3, H1, H3 · **Fixture:** `fixtures/t06_release_gate/` · **Config:** `configs/tracks/t06.yaml`

> Gate PASS/HOLD cho release dataset: bắt lỗi *im lặng* (JSON vẫn hợp lệ) như đảo class map, lệch bbox, trùng ID, rơi frame, map cũ.

**5 bước bắt buộc:** Import JSON/YOLO → So invariants & semantics → Đối chiếu parent manifest → Audit lỗi trọng yếu → PASS / HOLD + rework report

## 1. Dữ liệu có sẵn (offline)

| File | Nội dung |
|---|---|
| `releases/v1.0/` | Parent release: `annotations.json` (COCO), `release_meta.json`, `classes.txt`, `yolo_labels/`. |
| `releases/label_maps.json` | Lịch sử label map (`lm-2`, `lm-3`). |
| `releases/candidates/rXX/` | 20 release ứng viên (10 dev / 10 eval): `annotations.json` + `release_meta.json` (parent sha256…). |
| `releases.csv` | Danh sách release + split. |
| `images/` | 100 thumbnail mà annotation trỏ tới. |
| `gt/gt_releases.csv` | `is_defective, corruption_type` — chỉ evaluate. |

`manifest.csv` (input) và `gt/manifest.csv` (ground truth) chứa `source, license, split, sha256` — pipeline kiểm hash ở bước load.
**Pipeline không được đọc `gt/`** (GT guard trong `src.main` sẽ dừng với exit code 5).

**Dữ liệu thật (tuỳ chọn, nếu giảng viên đã chuẩn bị `data/real/`):** `data/real/coco/annotations_subset.json` (COCO thật) — tự inject 5 loại corruption để kiểm thử gate trên dữ liệu thật.

## 2. Output contract

`out/release_decisions.csv`: `release_id, decision ∈ {PASS, HOLD, REWORK}` (+ `root_cause` ∈ class_swap / bbox_shift / id_collision / dropped_frames / stale_map / clean).

`src.main` kiểm tra file và cột bắt buộc; thiếu → exit code 2.

## 3. Metric (đã cài sẵn trong `src/metrics/tracks.py::eval_t06`)

- **Primary — Silent-defect Detection F1** (đơn vị = release; positive = release lỗi bị chặn), split eval.
- Secondary: false-block rate trên release sạch, root-cause accuracy, runtime/100 mẫu.

python -m src.evaluate --track t06 --pred out/release_decisions.csv

## 4. Baseline (nhóm tự cài) + thí nghiệm công bằng

- **Baseline:** Chỉ parse JSON/schema + kiểm file tồn tại; không so semantic invariants.
- **Protocol:** ≥5 corruption types (3 vẫn parse được). 10 release sạch để đo false block. Mọi release đều có thay đổi lành tính → "có diff" không phải tín hiệu.
- Cùng pool / budget / seed 42 / heldout cho baseline và PoC. Báo cả kết quả bằng 0 hoặc âm.

## 5. Failure mode bắt buộc phải phân tích

JSON hợp lệ nhưng class mapping đã đảo; check chỉ khớp size file nên lọt bug.

Fixture đã cài sẵn một số case cho các failure mode này — nhóm phải tự tìm, minh hoạ bằng ảnh/metadata và nêu root cause.

## 6. Human review + quyết định

Diff chỉ rõ file, class, bbox cũ/mới, bằng chứng và người ký release.
Dùng `src/common/review.py` (queue, overrides, `AuditLog`), `src/common/contact_sheet.py` (HTML offline có nút Export CSV) và `src/common/decision.py` (GO/HOLD/REWORK + `reason_code` + `owner`).
